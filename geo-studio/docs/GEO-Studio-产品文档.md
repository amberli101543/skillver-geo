## 一、产品是什么

GEO Studio 是企业品牌在**生成式 AI 时代**的可见度运营工作台。它把「品牌在 ChatGPT、Claude、国内大模型等引擎里是否被提及、是否被准确复述」这件事，做成一条可重复执行的工作流：

**建品牌 → 录入知识 → 诊断跑批 → 看趋势与缺口 → 规划语义矩阵 → 生成内容初稿 → 分发到信源 → 定时复测 → 监测告警**

平台以**单用户 Studio**形态交付：一名运营者登录后，在一张纵向工作看板上完成上述全流程，无需切换多个系统。

### 价值主张

- **可测**：自动生成诊断问题集，对引擎实测并打分，形成提及率、正面率、准确率等基线。
- **可规划**：用语义矩阵把「用户想问什么 × 内容从什么角度讲 × 处于什么阶段 × 面向谁」系统化落格。
- **可生产**：按矩阵格子生成 AI 友好初稿，结合品牌断言提升事实密度。
- **可分发**：管理信源权重与分发任务，支持自动发布或导出稿件。
- **可持续**：定时复测沉淀趋势；阈值与跌幅告警帮助发现可见度下滑与错误信息。

### 页脚品牌语

> GEO 致力于提升品牌在生成式 AI 中的可见度与叙事准确性，实现诊断、内容、分发与监测的全链路闭环。

## 二、谁在用、怎么用

| 角色 | 在本版本中的用法 |
|------|------------------|
| 品牌 / 市场运营 | 维护品牌与断言、发起跑批、读趋势、处理告警 |
| 内容运营 | 维护语义矩阵、生成并编辑初稿、创建分发任务 |
| 策略分析 | 解读跑批明细、同步诊断缺口、调整矩阵优先级 |

本版本为**单用户本地/私有化 Studio**，不含多租户、团队协作与 RBAC。代理机构场景下通过「多品牌切换」管理多个客户品牌。

## 三、访问与登录

### 入口

- Web 看板：开发环境通常为 `http://localhost:5173`，预览构建为 `http://localhost:4173`
- 后端 API：默认 `http://localhost:3000`

### 登录

- 未登录时进入**登录页**；登录成功后进入主看板。
- 标题 **GEO Studio** 使用品牌绿色展示。
- 默认账号：`admin` / `123456`（由服务端环境变量 `STUDIO_USERNAME`、`STUDIO_PASSWORD` 配置，本地开发见 `backend/.env`）。
- 登录态为 JWT，看板右上角显示「用户名 · 退出」。

### 鉴权

- 除健康检查外，API 需携带鉴权信息（`X-Api-Key` 或登录后的 Bearer Token）。
- 登录页**不展示**环境变量配置说明，避免干扰终端用户。

## 四、界面与导航

### 视觉风格

- 参考 MongoDB 设计体系的深色头部 + 浅色卡片工作区。
- 主色：品牌绿 `#00ed64`；深色背景 `#001e2b`。
- 圆角、阴影、按钮样式在全站统一；头部与下方卡片圆角一致。

### 顶部结构

| 区域 | 内容 |
|------|------|
| 左侧 | **GEO Studio** 标题（绿色） |
| 右侧 | 当前用户名与退出 |
| 导航栏 | 按工作流时间线排序的模块快捷跳转 |

### 导航顺序（与工作流一致）

1. 多品牌  
2. 诊断跑批  
3. 趋势明细  
4. 语义矩阵  
5. 内容初稿（跳转至矩阵模块内的初稿能力）  
6. 信源分发  
7. 监测告警  

页面模块的纵向排列与导航顺序一致，用户可自上而下完成一次完整 GEO 运营周期。

## 五、功能模块说明

### 5.1 多品牌工作区

品牌是全局上下文：切换品牌后，诊断、矩阵、分发、告警等模块均作用于当前品牌。

**工具栏（单行）**

| 控件 | 说明 |
|------|------|
| 当前品牌 | 下拉仅显示品牌名称，不展示内部 ID |
| 新建品牌 | 弹窗录入名称、定义等 |
| 编辑 | 修正名称与定义（如乱码修复） |
| 删除 | 确认后删除品牌及关联数据 |
| 开始诊断跑批 | 对当前品牌一键全量诊断 |

**已移除能力**

- 跑批时的「临时竞品 / 诊断属性」可选参数（前端与 API 均已去掉）。  
- 对比题与属性题改由**竞品库**与**品牌断言**在服务端自动并入问题集。

---

### 5.2 竞品库

维护品牌长期关注的竞品名单。

- 说明：已存竞品会在跑批时**自动生成对比类诊断题**。
- 操作：输入竞品名称 → **添加**；列表中以标签展示，可删除。
- 与上方品牌工具栏同页，无需额外跳转。

---

### 5.3 品牌断言

记录品牌核心事实（如资质、功能、定价主张等）。

- 用于：内容初稿生成时注入事实；跑批后缺失事实类告警。
- 操作：添加断言文本、删除断言；**不展示「证据来源」字段**（界面已简化）。

---

### 5.4 AI 设置

配置真实 LLM 调用，驱动引擎实测、评分与内容生成。

| 能力 | 说明 |
|------|------|
| 模型目录 | 用户自行**添加模型**：显示名称、模型 ID、API Key |
| 保存 | 持久化到服务端；引擎与评分走 **live + LLM** 路径 |
| 已移除 | 内置模型列表、全局 Key 下拉、顶部「模式 / 当前模型」状态条 |

无有效模型配置时，相关 AI 能力会提示配置或回退规则逻辑（以实现为准）。

---

### 5.5 诊断跑批

**一键跑批**

- 基于品牌定义、竞品库、断言自动生成问题集。
- 逐题调用引擎连接器实测，再经评分流水线打分。
- 结果写入跑批历史，并更新指标快照与告警检测。

**跑批历史面板**

- 列表展示历次跑批时间、题量、核心指标。
- 可展开单次跑批明细：每题的问答、评分、情感、是否提及等。
- 可预览当前品牌将使用的**诊断问题集**（只读，无临时参数）。
- 跑批记录可标注评分模式（规则 / LLM，若后端返回）。

**引擎试跑**

- 独立面板：输入单题即时实测，**不写入**跑批历史。
- 用于调试提示词或快速验证某个问法。

---

### 5.6 定时复测

按固定间隔自动触发诊断跑批（后台 Worker 轮询）。

**配置区（单行布局）**

| 控件 | 说明 |
|------|------|
| 启用定时复测 | 开关 |
| 间隔数字框 | 默认 168（小时） |
| 间隔（小时） | 灰色标签，与数字框横排 |
| 保存配置 | 提交 |

保存后展示上次 / 下次复测时间（若已启用）。

---

### 5.7 趋势明细

三张折线图，展示品牌可见度指标随时间的变化：

| 指标 | 含义 |
|------|------|
| 提及率 | 诊断题中被提及品牌的比例 |
| 正面率 | 提及中情感为正面的比例 |
| 平均准确率 | 回答与品牌事实的一致程度 |

数据来自历次跑批写入的指标快照；新品牌跑批后才有曲线。

---

### 5.8 语义矩阵

把内容版图规划为**四维语义格子**：

| 维度 | 示例预设 |
|------|----------|
| 用户意图 | 品类认知、品牌了解、选型对比、购买决策… |
| 内容角度 | 推荐曝光、核心价值、竞品差异、案例背书… |
| 内容阶段 | 全阶段、认知、考虑、决策、留存 |
| 目标受众 | 通用受众、决策者、业务负责人、一线使用者… |

**格子管理**

- 添加 / 编辑 / 删除格子；每格有标题与优先级（0–100）。
- 卡片式展示：显示优先级、四维摘要、是否有初稿。
- 同一品牌下，「意图 + 角度 + 阶段 + 受众」四元组唯一。

**缺口同步**

- 从最近一次跑批结果分析语义缺口，一键同步为矩阵格子（带推荐优先级）。
- 可从品牌断言批量生成矩阵建议。

**内容初稿（矩阵内）**

- 选中格子可生成初稿（依赖 AI 设置与断言）。
- 支持编辑正文、变更状态（草稿 / 审核等）。
- 无断言时界面提示建议先录入断言。

---

### 5.9 信源与分发

**信源库**

- 维护信源名称、层级（共识 / 专业 / 社区 / 自有）、渠道类型。
- **权重**：数字框右侧灰色提示「权重 0–100」，与表单项同行对齐；数值越高分发优先级越高。

**分发任务**

- 将内容初稿绑定到信源，设置优先级与状态。
- 执行：支持连接器自动发布，或导出标准稿件人工发布。

**发布记录**

- 查看历史发布结果、外链与完成状态。

---

### 5.10 监测告警

**告警列表**

- 展示跑批后触发的告警：阈值类（提及率/准确率过低）、跌幅类、错误信息类等。
- 支持筛选、确认/关闭告警。

**阈值配置**

- 可调整提及率下限、准确率下限、环比跌幅上限等。
- 保存后对后续跑批生效。

## 六、诊断与评分（产品逻辑）

### 问题集构成

| 类别 | 触发条件 |
|------|----------|
| 品类 / 品牌 | 始终根据品牌定义生成 |
| 属性 | 来自品牌断言中的关键属性 |
| 对比 | 来自竞品库中的已存竞品 |

不再支持跑批时临时传入竞品或属性 CSV。

### 评分模式

- **规则评分**：基于关键词、情感与简单规则的默认可用路径。
- **LLM 评分**：配置有效模型与 Key 后，对引擎回答做更深度的提及/准确/情感判断；失败时可回退规则。

每次跑批记录可携带当次 `scoringMode`，便于明细中追溯评分来源。

### 引擎模式

- **Stub**：无外部 Key 时的模拟回答，用于演示与联调。
- **Live**：调用已配置 LLM，模拟检索增强型问答行为。

## 七、数据模型（产品视角）

```
Brand
 ├── Assertion（断言）
 ├── Competitor（竞品）
 ├── MatrixCell（语义格子：intent × angle × stage × audience）
 │    └── ContentDraft（内容初稿）
 ├── DiagnosticRun（跑批批次）
 │    ├── Question / EngineTest / TestScore（明细）
 │    └── → MetricSnapshot（趋势点）
 ├── Source（信源）
 │    └── DistributionTask → PublishRecord
 ├── RetestSchedule（定时复测）
 └── Alert（监测告警）
```

单用户版本：**无 tenantId**，所有数据按 `brandId` 隔离。

## 八、典型用户旅程

### 首次使用

1. 登录看板  
2. **新建品牌**，填写名称与一句话定义  
3. 在**竞品库**添加 1–2 个竞品，在**断言**录入 3–5 条核心事实  
4. 在 **AI 设置**添加可用模型与 Key  
5. 点击 **开始诊断跑批**，等待完成  
6. 查看 **趋势明细** 与 **诊断跑批** 明细  
7. 在 **语义矩阵** 同步缺口或手动加格，生成初稿并编辑  
8. 在 **信源分发** 建信源、创建任务并执行  
9. 在 **定时复测** 开启每周复测（如 168 小时）  
10. 在 **监测告警** 处理阈值告警  

### 日常运营

- 复测或手动跑批 → 看趋势是否改善 → 针对缺口补矩阵与内容 → 分发 → 关闭已处理告警。

## 九、当前版本边界

### 已交付（v1）

- 单用户 Web 看板全流程  
- 多品牌 CRUD（含删除）  
- 登录门禁 + API 鉴权  
- 竞品 / 断言 / 跑批 / 明细 / 试跑  
- 四维语义矩阵 + 缺口同步 + 初稿生成编辑  
- 信源权重 + 分发 + 发布记录  
- 定时复测 Worker  
- 趋势图 + 告警与阈值  
- AI 模型目录前台配置  
- MongoDB 风格 UI 与体验迭代（导航、单行工具栏、文案精简等）

### 未纳入本版本（见 v2 Backlog）

- 多租户、团队协作、RBAC  
- 多引擎 / 多 LLM 提供商切换 UI  
- 告警外推（邮件、IM、Webhook）  
- 高保真设计稿 / 移动端专项  
- 真实各平台引擎官方 API 全量接入（当前以代理引擎 + 规则/LLM 评分为准）  
- Figma 级组件库与对外 Open API
