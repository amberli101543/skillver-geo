# Skillver GEO-OS（最小执行版）

## 1. 事实源与边界

- 16 格、渠道、排期和发布状态仅以 `01-strategy/` 现有文档为证据源。
- `matrix/skillver-16-cells.json` 是 16 格机器可读正本；字段契约见 `schemas/skillver-16-cells.schema.json`。
- `ops/publish-log.csv` 只登记可核验的实际发布；字段契约见 `schemas/publish-log.schema.json`。
- 草稿在库不等于已发布。未知发布日期保持空值，不推测补写。
- 对比内容只建立选题，不补写未经证实的竞品能力、价格、效果或市场数据。

## 2. 封闭内测口径

发布前必须保持“封闭内测”语境，不得出现以下承诺：

- 开放注册
- 公开版
- 当前版本永久免费
- 保证 offer、保过或同义结果承诺

可使用已被 strategy 文档证实的口径：内测阶段、邀请码、内测零收费、不承诺 offer。实际内容仍需按源文档逐句核验。

## 3. 单格生产流程

1. 从矩阵选择一个 `cellId`，确认阶段、角度与来源。
2. 只使用已核实事实写母稿；对案例、数据、竞品结论标记待核实，不自行补全。
3. 生成渠道变体时保持核心事实与结论一致。
4. 发布前运行：

   `python scripts/validate_geo_assets.py`

5. 人工复核链接可访问、内容与来源一致，再发布。
6. 发布后只向 `ops/publish-log.csv` 新增一条记录；禁止用计划记录冒充发布记录。
7. 再运行验证器，确保 Schema、`cellId`、禁语和台账唯一性通过。

## 4. 发布台账规则

- `recordId` 和 `url` 全局唯一。
- `cellId` 只能是 `C01` 至 `C16`。
- `status=已发布` 必须有 HTTPS URL。
- `publishedAt` 未被证据确认时留空；`verifiedAt` 表示本地证据核验日期，不替代发布日期。
- 撤回内容保留历史记录并将状态改为 `已撤回`，不静默删除。

## 5. 每周最小复盘

- 统计 16 格中已发布覆盖数。
- 检查发布台账是否与真实链接一致。
- 检查封闭内测禁语命中数必须为 0。
- 抽查不同渠道是否保持同源事实。
- 将待核实事实退回业务或教研，不以排期压力替代证据。
