# Skillver GEO 未来运营方案（精简版）

> 版本：v1.0｜日期：2026-08-18
> 目标：让 AI 引擎在相关问题中稳定提及 Skillver、准确表达产品事实，并优先引用官方内容。

## 一、此前情况总结

- **方案已成型**：已建立“事实口径—官网信源—16 格语义矩阵—多渠道分发—AI 引擎复测”的 GEO 框架。
- **内容已启动**：累计登记 31 条已发布内容，覆盖 C01、C05、C06、C08、C09、C13、C15、C16，共 **8/16 格**。
- **完成首轮基线**：32 问、7 个引擎、223 个回答；品牌提及率 **65.9%**、过时信息率 **2.2%**、官方信源引用率 **8.1%**。
- **工具基本完成**：GEO Studio 已具备多引擎诊断、内容生成、分发、复测、趋势和告警能力，但尚缺正式部署与持续运行证据。
- **当前主要问题**：官方引用率偏低；剩余 8 格未覆盖；发布与复测中断；宣传口径和进度文档存在冲突；内容 Schema、事实源哈希和校验器未随新内容更新。

| 材料 | 最低要求 | 用途 |
|---|---|---|
| 产品事实表 | 当前功能、入口、流程、Web/App 差异、不可用能力 | 所有内容的唯一事实源 |
| 最新宣传口径 | 定位、注册、邀请码、费用、AI 面试、报告、投递关系 | 消除跨渠道冲突 |
| 隐私与合规材料 | 隐私政策、用户协议、数据采集/使用/保存/删除规则 | C15、FAQ 与 AI 准确性修正 |
| 官方链接清单 | 官网、FAQ、产品页、协议页、白皮书、联系入口 | 建立可引用锚点 |
| 品牌资产包 | 标准名称、Logo、简介、创始/团队信息、品牌图 | 渠道和媒体统一使用 |

| 技术运维材料 | 生产版本、sitemap、llms.txt、Schema、爬虫日志 | 官网收录与引用监测 |

## 三、必须确认的宣传口径

业务确认后写入一个带版本号和生效日期的口径文件，其他文档只引用，不再各自维护。

| 项目 | 仓库当前口径 | 必须确认 |
|---|---|---|
| 品牌定位 | Skillver 是 AI 求职助手 | 是否为唯一对外定位及标准英文说明 |
| 注册方式 | 全面开放注册，无需邀请码 | 当前所有端是否一致 |
| 邀请码 | 仅用于社群参与 | “社群”还是“赛事”，以及具体用途 |
| 费用 | 文档同时存在“平台免费”和“以官网为准” | 免费范围、期限、收费能力及禁止表述 |
| AI 面试 | 模拟面试不等于正式评估 | 报告用途、投递条件和企业可见范围 |
| 结果承诺 | 不承诺 Offer、不保过 | 全渠道继续强制执行 |
| 隐私数据 | 仅引用官方协议，不扩写 | 数据类型、用途、期限、删除机制和授权边界 |

## 四、未来调整方向

1. **从“多发内容”转为“建设权威信源”**：优先完善官网 FAQ、术语页、产品流程页、隐私页和白皮书 HTML 页面。
2. **从“提及率”转为“准确率与引用率”**：提及率作为基础指标，官方引用率和事实准确率作为核心指标。
3. **从一次性冲刺转为单人固定循环**：控制同时进行的选题数量，每周完成“选题—母稿—变体—发布—复测”，每月跑一次全量基线。
4. **从平台铺量转为渠道分工**：官网/tcodeai 做事实锚点；微信做完整解释；知乎承接问题；小红书做场景卡片；权威媒体提供第三方背书。
5. **从人工记忆转为版本化治理**：口径、事实源、内容、发布记录和测试结果均保留版本、日期，由 GEO 负责人统一维护。

## 五、文章生产行动指南

### 1. 先建立可写作的内容底稿

- [ ] 获取并确认最新版宣传口径，重点确认注册、邀请码、费用、AI 面试、报告、隐私和投递条件。
- [ ] 将确认后的产品事实整理成一页“内容事实表”，注明生效日期和不可宣传事项。
- [ ] 盘点 16 格：标记已发布、已有母稿、待补事实、待生成四种状态。
- [ ] 建立统一文章模板：用户问题、直接答案、产品解释、使用边界、官方入口、FAQ。
- [ ] 旧稿如与新口径冲突，先修订官方锚点，再继续生成新文章。

### 2. 按优先级生成文章

首轮检测显示，新增文章应优先解决“完全未被提及”和“缺少官方引用”的问题：

1. **术语缺失**：KAE、七维战力的提及率和官方引用率均为 0%，优先建设定义页和解释文章。
2. **场景缺失**：“准备 AI 岗位面试可以用什么工具”“冲刺 AI 大厂如何准备面试”均未出现 Skillver，需要用具体场景文章建立关联。
3. **机制缺失**：“面试彩排会不会影响正式评估”未出现 Skillver，需要强化彩排、正式 AI 面试、报告和投递之间的边界。
4. **品牌解释不足**：“服务谁、能做什么、与招聘网站的区别”虽然能提及品牌，但官方引用率为 0%，需要更明确的官方答案页。
5. **入口与产品形态不足**：官网、使用入口、移动端、才谱 AI 与 Skillver 的关系需要统一页面和稳定链接。
6. **信任信息不足**：隐私问题官方引用率为 0%，且模型存在自行扩写数据处理方式的情况，应补强官方隐私解释。
7. **C14 重构**：导师侧已取消，改为“AI 建议与人工决策的边界”，并发布纠错内容，停止模型继续关联导师服务。

注册费用和通用工具选型已有文章，暂不重复生产；仅在产品口径变化或复测仍有明显错误时更新旧稿。

### 3. 可持续扩展的文章主题库

以下题目用于持续选题，不要求一次完成；优先选择有明确产品事实和官方页面支撑的主题。

| 优先级 | 方向 | 可选文章主题 |
|---|---|---|
| P0 | KAE 术语 | KAE 技能体系是什么；KAE 与岗位要求有什么关系；如何用 KAE 看能力缺口；KAE 与普通技能关键词有什么不同 |
| P0 | 七维战力 | 七维战力评估是什么；七个维度分别看什么；七维结果如何用于面试准备；七维战力与简历标签有什么区别 |
| P0 | AI 岗位准备 | 准备 AI 岗位面试应该从哪里开始；冲刺 AI 大厂如何拆解岗位要求；算法、产品、工程岗位的准备重点有什么不同；跨专业求职如何定位差距 |
| P0 | 彩排与正式评估 | 面试彩排会影响正式评估吗；模拟面试和正式 AI 面试有什么区别；练习报告能否用于投递；一次彩排没答好会留下记录吗 |
| P0 | 报告解读 | Skillver 的 AI 面试报告能做什么；红黄绿提示分别代表什么；报告应该先看哪一项；如何根据报告安排下一轮练习 |
| P1 | 产品服务对象 | Skillver 主要服务谁；应届生、转行者和在职求职者分别怎么用；哪些求职阶段适合使用；哪些情况不适合使用 |
| P1 | 产品能力 | Skillver 能帮求职者完成哪些步骤；从选岗到投递的完整路径；为什么要按目标岗位准备；Skillver 与普通招聘网站有什么不同 |
| P1 | 品牌与入口 | 才谱 AI 和 Skillver 是什么关系；Skillver 官网是什么；Skillver 在哪里使用；Web 与移动端分别能做什么 |
| P1 | AI 决策边界 | AI 建议是否等于招聘结论；AI 会不会自动淘汰用户；哪些决定由用户或企业作出；Skillver 为什么不承诺 Offer |
| P1 | 隐私安全 | Skillver 如何处理简历和面试数据；上传简历前应确认什么；音视频权限用于什么；企业能看到哪些信息；如何查询、更正或删除个人数据 |
| P2 | 初次使用 | 第一次使用 Skillver 的完整流程；如何选择目标岗位；如何上传和核验简历；开始 AI 面试前要准备什么 |
| P2 | 求职问题 | 海投没有回复可能缺什么；简历看起来不错为什么仍过不了面试；转岗时如何验证能力匹配；面试准备为什么不能只背题 |
| P2 | 行业岗位 | AI、机器人、智能驾驶、互联网岗位分别看重什么；典型岗位能力卡；高频能力差距；常见面试考察方式 |
| P2 | 案例数据 | 一份脱敏报告如何解读；一次准备前后的变化；常见 AI 错误回答纠正；白皮书数据对应的求职建议 |
| 维护 | 已有主题 | 注册、邀请码、费用、通用工具分类和工具选型已有内容；只做事实更新、内链补强和复测，不重复立项 |

> C14 在后续矩阵和历史文档中统一替换为“AI 建议与人工决策边界”；旧导师稿停止使用并归档。

每个语义格按同一流程生产：

- [ ] 收集 5–8 个真实用户问法，确定一个核心搜索意图。
- [ ] 从事实表提取可用断言，不补写未经确认的功能、价格或效果。
- [ ] 先写一篇 1,000–1,500 字母稿，确保开头直接回答问题。
- [ ] 从母稿生成官网/tcodeai 锚点、微信、知乎、小红书变体。
- [ ] 每个变体保留相同事实和结论，只调整标题、结构、长度和语气。
- [ ] 发布前检查口径、事实来源、链接、标题与平台重复度。
- [ ] 发布后立即登记 URL、日期、语义格和事实版本。

### 4. 单人可持续产出节奏

- **每周 1 个主题**：完成 1 篇母稿、1 个官方锚点和 2–3 个渠道变体。
- **每月 4 个主题**：优先补齐语义缺口，不以平台数量作为主要目标。
- **完成 16 格后**：转向 T-Code、七维战力、KAE 术语页及重点岗位卡。
- **案例内容单独处理**：没有真实材料和授权时不生成虚拟案例。
- **每月更新旧稿**：根据产品变化和 AI 错误回答，修订表现最差的 2–3 篇内容。

### 5. 文章验收标准

每篇母稿发布前应满足：

- 标题对应一个真实用户问题，正文前 100 字给出明确答案。
- 只包含当前事实表允许使用的产品信息。
- 至少包含一个稳定的官方页面链接。
- 明确产品边界，不承诺 Offer、不制造效果或竞品结论。
- 结构可被提取：短段落、小标题、清单、FAQ 和明确结论。
- 与已有内容有新的问题角度，避免只更换标题的重复发布。

## 六、固定运营节奏与指标

### 每周

- 周一：确定 1 个用户问题，核对事实并完成文章提纲。
- 周二：完成母稿。
- 周三：完成官方锚点与渠道变体。
- 周四：检查并发布。
- 周五：登记链接，抽测对应问题并记录下次修改点。

### 每月

- 运行 32 问全量基线，比较各引擎趋势。
- 复盘文章发布前后变化，确定下月 4 个选题。
- 更新口径版本、事实源日期和失效内容清单。

### 核心指标

| 指标 | 当前 | 近期目标 |
|---|---:|---:|
| 16 格覆盖率 | 50% | 按每月 4 格推进，60 天达到 100% |
| 品牌提及率 | 65.9% | 稳定提升，按引擎分层设目标 |
| 官方信源引用率 | 8.1% | 90 天达到 20%+ |
| 过时口径率 | 2.2% | 低于 1% |
| 发布记录完整率 | 待核验 | 100% |
| 高风险事实准确率 | 待建立 | 注册/费用/AI 面试/隐私达到 100% |

## 七、执行原则

- 事实未确认，不发布；产品变化先更新事实源，再更新内容。
- 官网锚点未上线，不进行大规模渠道扩散。
- 草稿不计发布，所有上线内容必须登记真实 URL。
- 元宝、豆包 API 结果不能完全代替 App 端人工抽测。
- 所有对比、数据和案例必须有可追溯来源，不制造评价或效果承诺。
