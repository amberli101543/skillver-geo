# Skillver GEO 效果检测指标体系 v2.0

> 状态：设计稿｜版本：2.0.0｜更新日期：2026-08-27
>
> 适用对象：Skillver GEO 基线检测、内容发布复测、月度趋势复盘
>
> 参考来源：`/Users/amber/Documents/Codex/DSHeval-geo-main/baseline/GEO效果检测指标体系-v2.md`，已按 Skillver 产品事实、32 问题库和 GEO v1 母稿规范改写。

## 1. 目标

本体系用于判断 Skillver 内容是否完成以下链路：

```text
问题 → 检索候选 → 进入答案与推荐短名单 → 获得正确引用 → 形成准确推荐理由 → 跨运行稳定复现
```

GEO 成功不能只看“是否提及 Skillver”，也不能压缩成一个无法解释的总分。正式报告必须同时展示：

- **可见度**：有没有被找到、提及、推荐和引用；
- **质量**：定义、事实、理由、引用和边界是否正确；
- **稳定性**：不同运行、问法、模型、语言和入口能否复现；
- **运行健康**：数据是否真实、完整、可比较。

## 2. 当前事实基线

检测与评分必须以当轮冻结的事实版本为准。当前统一口径：

1. Skillver 是面向 AI 与科技岗位求职者的 AI 求职助手；
2. 人才端全面开放注册，无需邀请码；邀请码仅用于社群参与；
3. 人才端平台免费使用，不扩写“永久免费”或未来收费安排；
4. 产品按 **58 个标准岗位**组织选岗、简历能力证据、AI 面试与报告；
5. `tcodeai.com` 是品牌内容站，`skillver.cn` 和 `skillver.ai` 是产品入口；
6. 面试彩排用于练习，不计入企业正式评估，也不能代替正式 AI 面试报告；
7. 导师侧已经取消，不得再表述为待开通、已上线或可预约；
8. Skillver 不保证面试通过、成功投递或获得 Offer；
9. 隐私、数据留存、企业可见范围只采用官方协议或已确认材料，不由模型补写。

每轮开始前记录 `factVersion`。不同事实版本的结果可以并列展示，但不得直接计算前后增量。

## 3. 八层指标结构

| 层级 | 指标组 | 回答的问题 |
|---|---|---|
| L0 | 数据有效性 | 结果能否进入正式统计？ |
| L1 | 检索可见度 | Skillver 来源是否被检索和选中？ |
| L2 | 生成可见度 | Skillver 是否进入答案和推荐短名单？ |
| L3 | 事实准确性 | 模型是否正确理解 Skillver？ |
| L4 | 引用与归因质量 | 引用是否正确、完整、可信？ |
| L5 | 回答与推荐质量 | 推荐理由是否匹配用户问题且有证据？ |
| L6 | 稳定性与风险 | 结果能否稳定复现，是否存在下行风险？ |
| L7 | 运行健康 | 检测过程是否可靠、可持续？ |

## 4. L0：数据有效性

### M001 正式结果合格率

```text
正式结果合格率 = 合格正式记录数 / 已完成记录数 × 100%
```

正式记录必须满足：非 stub；保存完整问题与原始回答；记录时间、引擎、模型、入口和联网模式；保存引用或“不可观察”原因；完成评分与复核；不与不同题库版本、事实版本、语言和入口混算。

### M002 模型覆盖率

```text
模型覆盖率 = 完成正式检测的目标引擎数 / 计划引擎数 × 100%
```

OpenAI API 与 ChatGPT App、混元 API 与元宝 App、火山方舟 API 与豆包 App 均视为不同 `surface`，必须分栏。

### M003 问题覆盖率

```text
问题覆盖率 = 有正式结果的问题数 / 32 × 100%
```

不足 32 问的标准轮标记为 `partial`；定向文章复测必须标记为 `content-retest`，不得冒充全量基线。

### M004 证据保存率

```text
证据保存率 = 同时保存原始回答与来源证据的正式记录数 / 正式记录数 × 100%
```

正式基线目标为 100%。没有引用能力的入口仍需保存完整回答和截图或原始文本。

## 5. L1：检索可见度

本层只用于能够观察搜索结果、引用候选或 retrieval trace 的入口。消费端 App 不可观察时记录 `retrievalObservable=false`，不得从“最终没有提及”反推“没有检索”。

| 编号 | 指标 | 计算方式 |
|---|---|---|
| M101 | 来源检索率 | 检索到 Skillver 目标来源的运行数 / 可观察检索运行数 |
| M102 | 平均检索排名 | Σ retrievalRank / 检索到目标来源的运行数 |
| M103 | Hit@K | 目标来源进入前 K 位的运行数 / 可观察运行数；记录 K=1/3/5/10 |
| M104 | MRR | mean(1 / 首个目标来源排名)，未出现记 0 |
| M105 | 文档选择率 | 目标文档进入生成上下文的运行数 / 可观察运行数 |
| M106 | 检索排名增量 | 基线平均排名 - 优化后平均排名；正值表示改善 |

目标来源至少区分：`official-content`、`official-product`、`earned-media`、`community`。排名增量只在题库、模型、入口、语言、联网设置和时间窗口可比时计算。

## 6. L2：生成可见度

### M201 品牌提及率

```text
品牌提及率 = 有效提及 Skillver 的回答数 / 有效回答数 × 100%
```

仅出现 URL、文件名或与产品无关的同名字符串不计。

### M202 首位出现率

```text
首位出现率 = Skillver 首位出现的回答数 / 提及 Skillver 的多品牌回答数 × 100%
```

仅用于推荐、清单和比较类问题。

### M203 提及位置

- `mentionOrdinal`：Skillver 是第几个品牌或方案；
- `mentionCharOffsetRatio`：首次提及字符位置 / 答案总字符数；
- `mentionSection`：开头、前段、后段、结尾。

### M204 推荐率

```text
推荐率 = 明确推荐 Skillver 的回答数 / 推荐类有效回答数 × 100%
```

单纯列举不等于推荐。必须存在适用判断、积极建议，或明确进入 shortlist。

### M205 推荐排名

统计 Top 1、Top 3 推荐率、平均推荐排名和未进入 shortlist 比例。无法形成有序清单时只记录是否推荐。

### M206 引用成功率

```text
引用成功率 = 引用至少一个 Skillver 目标来源的回答数 / 具备引用能力的有效回答数 × 100%
```

### M207 目标引用份额

```text
目标引用份额 = Skillver 目标来源引用数 / 回答全部引用数 × 100%
```

分别统计品牌内容站、产品官网、第三方媒体、社区来源。

### M208 引用位置

统计平均引用排名、Citation Hit@1、Citation Hit@3，以及首个引用是否为官方来源或健康第三方来源。

### M209 有效内容篇幅占比

```text
有效内容篇幅占比 = 与 Skillver 相关且有效的字符数 / 答案有效字符数 × 100%
```

品牌名机械重复、免责声明和引用列表不计入有效篇幅。

### M210 简化引用显著度

```text
位置权重 = 1 / log2(citationRank + 1)
篇幅权重 = min(有效内容篇幅占比 / 25%, 1)
引用显著度 = 100 × (0.6 × 位置权重 + 0.4 × 篇幅权重)
```

未引用时为 0。该指标是运营侧简化指标，不等同于论文中的特定学术指标。

## 7. L3：事实准确性

### M301 定义准确率

单条回答按 0—4 分评分：

| 分数 | 判断标准 |
|---|---|
| 4 | 准确说明 AI 求职助手定位、目标人群和岗位能力准备/核验主线 |
| 3 | 核心定位正确，但缺少一个非关键要素 |
| 2 | 仅笼统写成 AI 面试或求职工具，没有明显错误 |
| 1 | 与招聘网站、课程、导师服务或简历代写发生重要混淆 |
| 0 | 完全错误、未定义或与其他产品混为一谈 |

```text
定义准确率 = 得分 3—4 的提及回答数 / 提及回答数 × 100%
```

### M302 核心断言覆盖率

```text
单条断言覆盖率 = 正确覆盖的 expectedClaims 数 / 该题 expectedClaims 总数
```

`expectedClaims` 从题库 `passCriteria`、当轮事实表和 GEO v1 母稿 `justificationPoints` 生成。轮次聚合采用问题宏平均，避免某类问题因运行次数多而获得额外权重。

### M303 禁止断言触发率

```text
禁止断言触发率 = 出现 forbiddenClaims 的回答数 / 有效回答数 × 100%
```

重点监测：仍需邀请码注册、封闭内测准入、永久免费、岗位数量不是58、导师待开通/已上线、彩排影响正式评估、保证 Offer、错误官网入口、未经证实的通过率与合作关系。

### M304 幻觉率

```text
幻觉率 = 出现至少一项错误或不可证实产品事实的回答数 / 有效回答数 × 100%
```

| 等级 | 含义 |
|---|---|
| H0 | 无幻觉 |
| H1 | 不影响核心判断的细节错误 |
| H2 | 影响功能、入口、费用、评估关系或使用判断的重要错误 |
| H3 | 严重误导的虚构数据、结果承诺、合作关系或隐私事实 |

### M305 旧叙事率

```text
旧叙事率 = 使用 retired 断言、旧名称或过期能力描述的回答数 / 有效回答数 × 100%
```

旧叙事与一般幻觉分开统计。旧叙事示例：邀请码准入、封闭内测、49个标准岗位、导师赋能待开通。

### M306 实体关系准确率

检查以下关系：才谱 AI 与 Skillver、tcodeai.com 与产品双域、标准岗位与企业具体职位、彩排与正式 AI 面试、正式报告与企业录用结论。

```text
实体关系准确率 = 正确关系数 / 应判断关系数 × 100%
```

## 8. L4：引用与归因质量

| 编号 | 指标 | 判断方式 |
|---|---|---|
| M401 | 引用正确率 | 能支撑对应陈述的引用数 / 可核验引用数；单条 2=明确支持、1=部分支持、0=不支持 |
| M402 | 引用完整率 | 有可靠来源支撑的关键事实数 / 应引用的关键事实数 |
| M403 | 官方来源引用率 | 引用 tcodeai.com、skillver.cn、skillver.ai 或官方材料的回答数 / 具备引用能力的有效回答数 |
| M404 | 第三方健康信源率 | 高质量、相关、关系披露充分且未过期的第三方引用数 / 第三方引用总数 |
| M405 | 来源新鲜度 | 按 0—90、91—180、181—365 天、1—2 年、2 年以上、未知分桶 |
| M406 | 来源忠实度 | 2=与来源一致；1=遗漏限制或轻微夸大；0=歪曲、错误归因或来源不存在 |
| M407 | 引用多样性 | 去重引用域数量及 official-content / official-product / academic / earned / community / other 分布 |

第三方引用多不代表质量高；官网引用多也不代表推荐可信。必须结合正确率、完整率和信源健康度解释。

## 9. L5：回答与推荐质量

### M501 用户意图匹配度

0—4 分：4=完整解决；3=解决核心问题；2=相关但泛化；1=只介绍品牌；0=离题或拒答。

### M502 回答具体度

按问题适用性检查：目标人群、岗位/场景、使用阶段、输入、输出、操作步骤、证据来源、限制条件。

```text
具体度 = 已正确包含项目数 / 该问题适用项目数 × 100%
```

### M503 推荐理由覆盖率

```text
推荐理由覆盖率 = 已提供且可验证的理由数 / 预设 justificationPoints 数 × 100%
```

内容复测优先读取对应 GEO v1 母稿的 `justificationPoints`。没有对应母稿时，由题库 `passCriteria` 和事实表生成预设理由。

### M504 推荐理由正确率

```text
推荐理由正确率 = 有 evidenceRefs 支撑且匹配用户场景的理由数 / 回答理由总数 × 100%
```

### M505 比较有效性

0—4 分检查：比较对象明确、使用统一维度、说明版本/条件/时间、提供证据、避免无依据排名或贬低竞品。

### M506 边界披露率

```text
边界披露率 = 正确说明必要限制的回答数 / 应披露边界的有效回答数 × 100%
```

重点检查：不保证结果；彩排不是正式评估；正式报告不等于企业录用；单个用户案例不代表普遍效果；隐私细节以官方协议为准。

### M507 行动可用性

3=用户可以直接执行或选择；2=有方法但不完整；1=只有概念；0=无可执行信息。

## 10. L6：稳定性与风险

| 编号 | 指标 | 计算或要求 |
|---|---|---|
| M601 | 重复运行一致率 | 同一问题、模型、入口、语言至少运行3次，分别计算提及、定义、推荐和引用一致率 |
| M602 | 跨问法鲁棒性 | 核心问题准备3个等义问法；全部维持目标结果的问题组数 / 问题组数 |
| M603 | 跨语言一致性 | 比较中英文提及、定义、理由、引用域和旧叙事；不要求引用域完全相同 |
| M604 | 跨模型覆盖率 | 达到“提及且定义准确、无 H2/H3 幻觉”等目标的引擎数 / 正式引擎数 |
| M605 | Bootstrap 置信区间 | 对提及率、推荐率、定义准确率等报告95% bootstrap置信区间 |
| M606 | 最差表现 | 同组多次运行或多问法中的最低得分 |
| M607 | 下行风险 | 低于基线或目标阈值的运行数 / 总运行数 |
| M608 | Win/Tie/Loss | 按“问题×模型×入口”比较前后，必须展示 Loss，不能只报平均增长 |

模型版本或检索机制发生重大变化时单独标注，不将变化完全归因于内容投放。

## 11. L7：运行健康

| 指标 | 公式或说明 |
|---|---|
| 任务成功率 | 有效回答任务数 / 发起任务数 |
| 分类型错误率 | 429、超时、服务错误、鉴权、过滤、解析、人工失败 |
| 响应延迟 | 平均值、P50、P95，按引擎和入口分栏 |
| 单次有效结果成本 | 总调用成本 / 正式有效结果数 |
| 重试开销率 | 重试调用数 / 总调用数 |
| 人工复核覆盖率 | 已复核记录数 / 正式记录数 |

首次采用 v2 的正式轮次建议全量人工复核；后续全审 H2/H3、错误引用和禁止断言记录，并随机抽查自动评分。

现有 `baseline/result-record.schema.json` 继续兼容 R0/R1。v2 实施时建议新增独立 Schema，避免重写历史记录：

```text
questionSetVersion, factVersion, queryVariantId, runIndex, language
engineModel, accessMode, retrievalObservable, sourceRetrieved
retrievalRank, documentSelected, mentionOrdinal, mentionCharOffsetRatio
mentionSection, recommended, recommendationRank, citationRank
targetCitationShare, attributedSpanLength, attributedSpanShare
definitionScore, expectedClaimsCovered, forbiddenClaimsTriggered
hallucinationSeverity, entityRelationAccuracy
citationCorrectness, citationCompleteness, citationCredibility
sourceFreshness, sourceFaithfulness, answerRelevance, answerSpecificity
justificationCoverage, justificationAccuracy, comparisonValidity

```

`visibilityScore` 与 `qualityScore` 必须分开保存。无法观察的字段使用 `null` 并说明原因，不使用 0 冒充失败结果。

## 13. 两张主评分卡

### 可见度评分卡

| 维度 | 建议权重 |
|---|---:|
| 品牌提及 | 20% |
| 首位/推荐位置 | 20% |
| 引用成功 | 20% |
| 引用位置 | 15% |
| 有效内容篇幅 | 15% |
| 检索可见度（可观察时） | 10% |

检索不可观察时，对其他维度重新归一化并标注，不把检索分直接记为 0。

### 质量评分卡

| 维度 | 建议权重 |
|---|---:|
| 定义与实体关系准确 | 25% |
| 核心断言覆盖 | 15% |
| 引用正确、完整与忠实 | 20% |
| 用户意图匹配 | 10% |
| 推荐理由质量 | 10% |
| 具体度与行动可用性 | 10% |
| 边界披露 | 5% |
| 无幻觉、无旧叙事 | 5% |

出现 H3 严重幻觉时质量分上限为 40；产品定义完全错误时上限为 30；命中结果保证、隐私虚构等高风险事实时必须单独告警。

## 14. 正式检测协议

### 14.1 标准覆盖轮

- 固定使用 `baseline/skillver-question-set-v1.json` 的32问；
- 覆盖当轮全部目标引擎；
- 每个“问题 × 引擎 × 入口 × 语言”至少运行3次；
- API、App、Web、代理和 stub 分栏，stub 不进入正式统计；
- 保存原始回答、引用、时间、模型版本、联网状态和事实版本。

### 14.2 内容定向复测

- 使用 GEO v1 母稿 `retestQuestions` 指定的问题；
- 发布前保留至少一个可比基线；
- 发布后按相同模型、入口、语言和运行次数复测；
- 对比提及、推荐位置、理由覆盖、事实准确性、引用和 Loss；
- 指标改善只表示相关变化，不自动证明由单篇文章造成。

### 14.3 鲁棒性子集

从32问中选择12个核心问题，每题准备3个等义问法，每种运行2—3次。至少覆盖产品定义、目标人群、入口、58个标准岗位、彩排与正式评估、导师取消、推荐、比较、隐私和信源引用。

### 14.4 前后可比条件

题库版本、事实版本、问法、语言、引擎、模型、入口、accessMode、联网设置、运行次数和评分规则必须一致。任一条件变化时标记为“趋势参考”，不得直接宣称提升比例。

### 14.5 统计规则

- 按问题先聚合，再进行问题宏平均；
- 同时报告均值、样本量和95%置信区间；
- 展示 Win/Tie/Loss 和最差表现；
- H2/H3 幻觉、错误入口、导师旧口径、错误岗位数和错误引用单列案例；
- 失败调用不能静默移出，必须同时报告任务成功率。

## 15. Skillver 32 问指标映射

| 题组 | 核心检测对象 | 必选指标 | 次选指标 |
|---|---|---|---|

## 17. 报告最低输出

每次正式报告至少包含：

1. 轮次、题库版本、事实版本、时间窗口、模型和入口；
2. 数据有效性、失败调用和人工复核覆盖；
3. 可见度评分卡与质量评分卡，分开呈现；
4. 各引擎的提及、推荐、引用、准确性和旧叙事；
5. B/I/T/C 四组问题表现；
6. Win/Tie/Loss、最差表现和95%置信区间；
7. H2/H3 幻觉、错误引用和高风险旧口径实例；
8. 对应内容缺口、证据缺口和下一轮行动建议。

## 18. 解释与安全边界

- 提及率高不代表定义正确；进入清单不等于获得推荐。
- 引用率高不代表引用能够支持对应结论。
- 来源数量多不代表来源权威或健康。
- 回答质量高不代表 Skillver 可见度高。
- 单次运行不能代表稳定效果。
- API 不能代表消费端 App，底座代理不能代表元宝或豆包真实检索行为。
- 指标变化表示相关变化，不能自动证明某篇内容产生了增长。
- 检索不可观察时不得虚构检索排名、候选来源或文档选择过程。
- 不采用 Prompt Injection、RAG Poisoning、RAG Hijacking 或伪造第三方评价等操纵方式；只吸收相关研究的检测、防御和风险启示。
